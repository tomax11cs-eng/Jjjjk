## What this project is

A single-page CZK → EUR currency converter, set up as an installable PWA so iPhone users can "Add to Home Screen" and use it like a native app. The whole app lives in `index.html` — markup, styles, and logic are inlined; there is no build step, no package manager, and no backend.

Files that ship alongside `index.html`:

- `manifest.json` — PWA metadata (name, theme color, icons).
- `sw.js` — service worker. Pre-caches the app shell (`./`, `index.html`, `manifest.json`, the three icons); for the Frankfurter API uses a network-first-with-cache-fallback strategy so the last good rate is available offline. Everything else falls back to a cache-first match.
- `icon-180.png` — Apple touch icon (home screen on iOS).
- `icon-192.png`, `icon-512.png` — PWA manifest icons.
- `README.md` — user-facing (Slovak) quickstart; keep it in sync with this file when behavior changes.
- `.github/workflows/pages.yml` — CI/CD, see Deployment below.

Icons are generated by `/tmp/make_icon.py` (kept out of the repo; regenerate if the visual identity changes — gradient and labels are defined there).

## Running it

Open `index.html` in a browser. There is no dev server, no `npm`, no tests. The service worker only registers under HTTPS or `localhost`, so loading the file via `file://` will skip the offline-cache path but the page still functions.

## Deployment

`.github/workflows/pages.yml` deploys the repository root straight to GitHub Pages on every push to `main` (or manual `workflow_dispatch`), no build step — it just uploads the checked-out tree via `actions/upload-pages-artifact` and publishes it with `actions/deploy-pages`. This means anything committed to the repo root is served as-is; don't add files there that shouldn't be public.

## Architecture notes

- **Exchange rate source:** the page fetches `https://api.frankfurter.app/latest?from=CZK&to=EUR` on load. Frankfurter mirrors ECB reference rates and updates on business days (~16:00 CET). It is free, keyless, and CORS-enabled — do not swap it for an API that requires a key without first asking the user.
- **Two-way binding:** both input fields (`#czk`, `#eur`) edit the same conceptual amount. A `direction` flag tracks which side the user is currently typing in, so `recalculate()` knows whether to multiply by `rate` or divide. The swap button (`#swapBtn`) just exchanges the two field values and flips `direction` — it does not re-fetch the rate.
- **Offline behavior:** once the rate is fetched, conversions work without network. There is no caching of the rate across reloads — a fresh fetch happens every page load, which is also how the "daily updated" guarantee is satisfied.
- **Cache versioning:** `sw.js` keys its cache as `CACHE = 'czk-eur-v1'`. Bump this string whenever a precached shell asset (`index.html`, `manifest.json`, icons) changes, otherwise returning clients keep serving the stale cached version — the `activate` handler deletes any cache key that doesn't match the current constant.

## Conventions

- UI strings are in Slovak. Keep them in Slovak unless the user asks for another language.
- Keep the app a single self-contained file unless complexity genuinely demands splitting it. Do not introduce a framework, bundler, or package.json without being asked.
